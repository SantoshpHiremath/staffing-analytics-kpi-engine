# Staffing Analytics KPI Engine

A tested TypeScript project that implements a semantic layer, TypeScript KPI projectors, and a React UI for staffing and workforce-management metrics. It follows the pipeline shape metric definition, semantic layer, data feed, React UI, and is written in TypeScript end to end.

## What it does

The project builds four staffing KPIs end to end, from a domain model through a semantic layer to a typed React component.

- **`src/types.ts`**: the domain model: `Requisition` (a business unit's request to fill a role) and `Placement` (the resulting worker assignment) as two related but independently queryable fact tables, plus `DimensionFilter` and `AccessScope` types.
- **`src/projectors/fillRate.ts`**: Fill Rate: filled / (filled + cancelled) requisitions. Still-open requisitions are deliberately excluded from the denominator, since including them would understate the rate for any period with recent, in-flight requisitions.
- **`src/projectors/timeToHire.ts`**: Time-to-Hire: average days from requisition open to fill. It also exports `weightedAverage()`, used to roll up several dimension-sliced results into one overall figure correctly. A naive average-of-averages overweights smaller-sample slices, and the test suite shows it gives a different number on the fixture data (16.02 weighted vs. 17.1 naive).
- **`src/projectors/turnover.ts`**: Turnover Rate: share of placements that ended early, out of placements that have actually ended (active placements are excluded from the denominator, the same terminal-state pattern as fill rate).
- **`src/projectors/costPerHire.ts`**: Cost-per-Hire: the cross-grain join in this project. Cost lives on the `Requisition` record; placement/outcome data lives on the separate `Placement` record. The join is explicit (by `requisitionId`, via a `Map`), not assumed positional alignment, and a filled+fee requisition with no matching placement (a data-integrity gap) is excluded rather than treated as free. `findOrphanedFilledRequisitions()` surfaces these as a diagnostic.
- **`src/access.ts`**: every query is scoped to the business units a caller is allowed to see, both at the filter level (an explicit out-of-scope request throws `AccessDeniedError`) and at the row level (an unscoped query still silently excludes out-of-scope rows).
- **`src/semanticLayer.ts`**: the single entry point (`getKpi`, `getKpiByDimension`) a UI calls to get any named metric, sliced by any supported dimension, scoped to what the caller can see.
- **`src/ui/KpiDashboard.tsx`**: a small React + TypeScript component consuming the semantic layer directly: metric tabs, an overall KPI card, and a business-unit breakdown, all typed end to end from raw dataset to rendered output.

## Data

All data is synthetic, generated by `src/generateData.ts` with a seeded PRNG. The semantic layer is a small, hand-built TypeScript module, and the dataset interface is built so a real database or an established semantic-layer tool (e.g. Cube, dbt Semantic Layer) can replace it.

## Results

48 tests pass (`npm test`, Vitest), and `tsc --noEmit` passes under `strict: true` and `noUncheckedIndexedAccess: true`. The latter caught two possible-`undefined` bugs in the data generator during development, fixed with explicit runtime checks rather than non-null assertions.

## Tests

48 tests (`npm test`, Vitest), including:

- Hand-computed expected values against a small fixture dataset (`tests/fixtures.ts`) for every projector: not just "the function runs," but "the function returns exactly the number I computed by hand."
- A regression test proving `weightedAverage()` gives a different result than a naive average-of-averages whenever sample sizes differ across slices.
- A cross-grain-join test proving an orphaned filled requisition (fee present, no matching placement) is excluded from cost-per-hire rather than mis-joined or treated as zero cost.
- Access-scoping tests covering both the explicit-request-denial path and the silent row-level exclusion path.
- React component tests (`@testing-library/react`) confirming the UI re-queries the semantic layer on tab switch (not caching a stale value), renders one row per in-scope business unit, and surfaces the low-confidence warning when sample size is small.
- `generateData.ts` sanity tests: deterministic given a seed, non-degenerate status distribution, every placement's `requisitionId` actually exists in the requisitions array.

```bash
npm test             # 48 tests, Vitest

                      # plus the access-scoping and data-integrity checks
```

## Notes

Two issues found and fixed during development:

**1. `getKpiByDimension` threw `AccessDeniedError` for a scoped-out caller instead of just not showing that dimension value.** The function discovered dimension values (e.g. "which business units exist?") from the entire unscoped dataset, then queried each one, so a caller scoped to `["Logistics"]` would hit an error the moment "Manufacturing" came up, rather than never seeing it. The access-scoping test suite (`tests/access.test.ts`) caught it. I fixed it by filtering dimension-value discovery through `isBusinessUnitInScope()` before querying each value, and added a dedicated regression test (`getKpiByDimension only returns dimension values the caller is scoped to see`).

**2. The React component tests failed with "multiple elements found"** because React Testing Library does not auto-clean the DOM between tests outside a framework with built-in `afterEach` hooks. Every `render()` call left its output mounted, so the second test's query matched both the first test's leftover DOM and its own. I fixed it by adding an explicit `cleanup()` call in `tests/setupTests.ts`'s `afterEach`.
